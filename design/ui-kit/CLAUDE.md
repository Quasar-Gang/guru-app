# 這個專案的 UI 規則

UI 全部來自 mist 設計系統。**寫任何畫面之前先讀 `ui/COMPONENTS.md`**（一頁，有元件清單與用法）。

## 四條鐵則

1. **`ui/` 整個資料夾是唯讀的。** 不要改裡面任何檔案 —— 那是從設計系統複製過來的，會被覆蓋更新
2. **頁面只放 class，不寫樣式。** 不准出現 `style="color: ..."`、不准在頁面裡寫 `<style>` 規則、不准寫死顏色或尺寸
3. **缺元件時不要自己新寫一個。** 先確認 `ui/COMPONENTS.md` 真的沒有；確定沒有的話**回報給設計系統的擁有者**，由他在設計系統裡新增後重新複製 `ui/` 過來
4. **真的來不及時**，可以寫進 `local-overrides.css`（只有這個檔案能寫樣式）。但它會被 `./check.sh` 列為債務，之後要回庫

## 新頁面怎麼開始

複製 `pages/_template.html`，改檔名，然後改內容。**不要從空白檔案開始** —— 範本裡有正確的 CSS 引入順序、表面分層結構、與限寬容器。

## 改完一定要跑

```bash
./check.sh
```

它會抓：寫死的顏色與尺寸、頁面裡的 inline style、頁面層新增的樣式定義、引用了不存在的 token、還沒回庫的 override。**沒過就是有問題，不要忽略。**

## 傳資料進元件

需要把數值（進度百分比、圖表高度）傳進元件時，只能用這三個變數，不能改其他視覺屬性：

- `--mist-progress-value` 進度條填滿比例
- `--mist-stem` lollipop 的柱高
- `--mist-bar` 密集細線圖的單根高度

例：`<div class="mist-progress__bar" style="--mist-progress-value: 62%"></div>`

## 風格的硬約束

完整版在 `ui/STYLE.md`。最常被違反的四條：

1. **彩色只做點綴** —— 橘紅與淡藍只能出現在 badge、圓點、頂規。九成畫面必須是灰白黑
2. **不用陰影做層次** —— 需要層次時往表面亮度階梯找一階（page → app → card）
3. **同一區塊內字級要跳級** —— 不要 14 配 20，要 12 配 40 這種
4. **圖表用線不用面** —— 不要實心色塊圖表
